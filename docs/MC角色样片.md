# 《一张皮肤，怎么让角色动起来？》30 秒动作样片

用项目里的 `avatar/mc_mon.png` 讲清三件事：一张图提供各面的外观，关节提供局部旋转，时间决定旋转到哪一步。面向初学者；演示的是本项目的轻量方块角色，不把示意步态当成 Minecraft 游戏引擎的实现。贴图是用户提供的原始 64×64 RGBA PNG，透明外层和细手臂布局按源图保留。

**规格**：1920×1080、30 fps、900 帧；中文配音和画内字幕，无配乐。画内字幕统一白字细黑描边、无底框；与角色标签分开。网页和 MP4 共用这一版，网页以配音的媒体时间驱动画面；MP4 不包含网页控件。这部既有样片的画内验收参考采用月白底、青黑正文、青色连接线；不是网站主题，也不作为新版 Hadoop 的画风默认值。新作的外壳与演出规则见 [SKILL.md](../SKILL.md)。除皮肤外不使用外部绘图素材。

| 镜号 | 时间 | 口播重点 | 关键画面与验收 |
|---|---|---|---|
| 01 | 0–2.80 s | 一张小小的皮肤 | 原图在左，角色走入画面，给观众先看一眼角色全貌。 |
| 02 | 2.80–9.60 s | 把皮肤贴到头、身体和四肢 | 依次高亮六个部件的贴图区域，右边对应部位亮起。 |
| 03 | 9.60–15.63 s | 手臂绕肩膀转 | 念到绕肩时，角色和肩关节示意图同步抬臂，再给读图时间。 |
| 04 | 15.63–22.40 s | 对侧手脚一起向前，下一步交换 | 侧前方看两组对侧肢体；先停在第一步，再随「下一步」换到另一组。 |
| 05 | 22.40–30.00 s | 点头、贴图决定外观、关节决定动作 | 同一角色转向、点头、定格；保留录音片尾的 AI 生成提示。 |

剪接表见 `works/mc-avatar/narration.ts`，分别记录原音频剪口、实测开口/收声和目标帧。字幕只覆盖实测口播区间，句尾保留约 0.1 秒阅读余量（按帧取整）；亮部、抬臂、换步等由实录关键词映射到动作帧。按录音速度局部调整镜头切点与停留，成片仍为 30 秒。用 `bun run avatar:dub` 从 `works/mc-avatar/dub/p1.mp3` 重新生成 `narration.mp3`，不覆盖原始录音或 `p1.txt`。源录音虽以 `.mp3` 结尾，实际为 WAV；FFmpeg 按内容识别。剪接在停顿间进行，保留原语速，每段切口做 8 毫秒淡入淡出。网页和 `bun run avatar:render` 直接读取已剪接音轨，不依赖原始录音。

角色预览页允许本地换 PNG、选择「自动／标准／细手臂」、调角度和时间。换图只作用于角色预览，不会上传或替换样片中的原图。自动识别以两条手臂贴图区的透明空列为线索，非规范贴图可手动选择。角色由盒面及刚性转轴组成，不做布料、连续网格变形或物理步态。

## 在其他作品里复用

用 `avatar/skin.ts` 的 `prepareSkin(image)` 解码贴图一次，然后在现有场景的绘制函数里使用 `avatar/draw.ts` 的 `drawAvatar`：

```ts
drawAvatar(ctx, skin, {
  x: 1240, y: 810, scale: 15, yaw: 0.28,
  action: 'point', time: localFrame / 30,
});
```

`x` 和 `y` 是脚底位置，`scale` 是每个模型像素的绘制比例，`yaw` 为弧度。动作可选 `idle`、`walk`、`look`、`point`、`nod`。`time` 用镜头的局部秒数，不另外计时；这样播放、跳转和导出使用同一帧姿态。可用 `intensity: 0` 绘制静止姿态。样片的 `works/mc-avatar/film.ts` 是完整例子。新作可传入自定义 `pose`，用 `headScale` 对头部内外层同步微缩放；需要展示物体交接时，用 `handAnchor(skin, view, hand)` 计算手部投影，释放后把道具交给场景锚点，而不是把角色限制在侧栏位置。
