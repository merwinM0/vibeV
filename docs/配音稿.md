要按省算销售额，还要能查一笔订单。这不是一条流水线，先看各层怎么分工。

十一月十六日的订单，放进当天的目录。文件可以存成 Parquet，方便后面扫描。

别一单存一个文件。同一分区的小文件合并，记录照旧。

这就是 HDFS。NameNode 管目录和块的位置，DataNode 才存数据。

大文件按配置切成块。画面这三块只是示例，可以分开存到不同机器。

写文件，先向 NameNode 申请，拿到目标位置。然后直接把数据发给 DataNode。

看清楚，是同一个 B 二沿管线传，每台留一份。这里设成三份，不是固定值。

这里把副本分到两个机架。一边掉线，另一边可能还有可读的副本。

读也是先问位置，再直接从数据节点拿块。有近的可用副本，就优先读近的。

A 节点的心跳断了。超时后，它被标记为不可用。还有副本，就改从 B 节点读。

NameNode 安排补副本。B 节点把块复制给 D 节点，可用副本回到三份。这能降低风险。

目录服务也能做高可用。备用节点同步日志，满足条件时接任，数据块不用搬。

仓库里的数据不动。按省汇总的任务，去 YARN 申请资源。

资源管理器给全局分资源。各台机器的节点管理器，管本机容器、报状态。

先分一个容器，启动应用主管。它再申请资源，由节点管理器启动任务容器。

容器给任务运行环境、算力和内存。旁边那个数据块，装的才是文件内容。

任务能挨着数据跑，就少搬数据。但也得看附近有没有空余资源。

同一道题，可以用 MapReduce，也可以用 Spark。不必两道都走。

把输入分成几份，每个 Map 任务读自己那份，好几台机器可以一起干。

省份当键，金额当值。三条就变成：江苏一百、广东八十、江苏五十。

如果同一个 Map 里有两条江苏，可以先做局部求和。但这一步不是必需的。

Shuffle 先分区，再传输、排序。看，两条江苏汇到一起。

每组各自数单、加金额。江苏两笔，共一百五十元；广东一笔，八十元。

汇总结果写回 HDFS，另放一个目录，不覆盖订单明细。

换成 Spark，先把计算排成一张依赖图。Driver 协调各阶段和任务，Executor 来执行。

这里是 YARN 分资源，Spark 跑计算。换一种集群管理环境也可以。

中间结果用得多，可以缓存，下回直接复用。但 Shuffle 仍可能用到磁盘。

经典批处理和通用计算，是两种选择。都能读写 HDFS。

十一月十六日，各省卖了多少？在 Hive，用一条 SQL 就能把问题说清楚。

Metastore 记的是列、分区和文件路径。订单文件还在 HDFS。

既然按天分了区，这条查询只扫十六日。旁边两个日期不用读。

Hive 的查询服务接到 SQL，查元数据、做优化，再把执行计划交给计算引擎。

Hive 是入口，不是存储，也不负责分资源。用哪个引擎，要看版本和配置。

回来的结果是每个省的订单数和销售额。可以画成图，也可以写进汇总表。

写入时，先记预写日志，也更新内存。后台把内存里的数据刷成 HFile，通常落在 HDFS。

查得快，不代表数据新。如果服务表每天才装一次，秒回的也可能是旧状态。

Hive 适合扫表汇总，HBase 适合按行键读写。
