# 章纲与演出提案｜待审稿后分镜

[项目简报](brief.md) · [纯口播](配音稿.md) · [示例与查证](article.md)

## 视觉边界

- **MC 只出现于案例和角色。** 交易站柜台、橡木、圆石、绿宝石与主持人使用 Minecraft 方块元素。案例收起后，只保留主持人和小型货物图标作为识别线索。不把 Hadoop 组件画成 MC 方块，也不伪装成游戏里能搭出的装置。
- **网页主题和旧版 Hadoop 一致。** 从共享的 `ui/site.css` 继承页面底纹、顶栏、控件，不另做浅色网页。暗色舞台内才使用大标题、栅格、等宽路径、审阅面板和泳道。数据亮青、控制琥珀、故障珊瑚红；传输尾点和落位回波只标记正在发生的事件，不铺满背景。
- 开场左边是交易台，右边是日志面板；进到 HDFS 后保留「交易明细」文件名作为位置锚点。数据字节走带箭头的实线；元数据请求、读写目标和控制消息走虚线；依赖说明用点线。每条主要线有动词标签，不靠颜色区分。ACK 与数据同在下方泳道，但用反向虚线和 `ACK` 标签，不能像数据回流。
- 画内口播字幕拟用白字细黑描边、无底框，留至少 5% 安全边距；图解标签不复读整段旁白。下面给出每章能脱离旁白成立的屏幕短句，正式镜号和字幕时间等确认后再做。

## 八章推进

每行首句对应[口播稿](配音稿.md)的段首，方便审稿定位。动作表给的是触发词和状态，不是计时表。

| 章 / 口播起点 | 画面任务与静音标签 | 角色动作：开始 → 触发 → 收势 |
|---|---|---|
| **01 两条日志就是两笔吗？**「昨晚，方块镇的交易站……」 | 开场即见橡木和两张同号交易单；只露出编号与 `12`，先不揭底。标签：`收到两条，成交了几笔？` | 柜台旁侧身入画 → 「出现了两次」时抱起两张单据，交替低头比对 → 摊手转向观众，停在问句后。 |
| **02 从哪里取、怎样不断档？**「先说数据从哪儿来。」 | 点击与扣款成功作对照；服务端日志接入采集器，依次点亮 `读到 → 原文落地 → 更新进度`。在后两步之间标出一次中断，恢复箭头回到旧检查点。标签：`重复投递 ≠ 再成交`。 | 看向日志面板 → 「原文存下来」时双手递出日志卡；「重启了呢」时停步、回头指向旧标记 → 侧身站住，给重放路径让位。 |
| **03 六条进来，最后算出什么？**「现在来动手算。」 | 六条依次进入验证、去重、日期归档和汇总；屏幕显示 `6 次投递 − 1 条坏行 − 1 条重复 = 4 条有效记录`、`4 条有效 = 3 成功 + 1 失败`，然后分货物得 `3 笔 / 26 颗`。结果旁常驻 `1 条待核`，晚到不等于重复。 | 侧站表格外侧 → 「问号」时俯身查看并把问题卡移入隔离栏；「同一个事件编号」时双手把同号卡叠齐；「十七日凌晨」时转身把卡放回十六日 → 点头一次，退到边缘，等观众验算。 |
| **04 日期、文件和列各管什么？**「有了可用的数据，文件怎么摆？」 | 并排展示 `原始 / 有效明细 / 隔离`；先在目录中选日期，再在 Parquet 示意中选列，最后比较每笔一文件与批量写文件。标签：`先选日期目录，再按需读列`、`同一分区内可合并小文件`。 | 起手看目录 → 「十六日」时抬臂对准对应目录；「需要的列」时横向扫臂停在货物与金额 → 收臂保持侧视，不盖住路径。 |
| **05 一个文件怎么变成块？**「现在把同样的交易明细放大。」 | `小样例` 切到明确标注 `放大演算：300 MiB` 的文件条，按 `128 / 128 / 44` 拉开；再给每块展开三份副本。标签：`1 个文件 · 3 个逻辑块 · 9 份块副本`。之后分开显示 NameNode 索引与 DataNode 字节。 | 站在文件条下方 → 「切出几块」时抬臂依次指两条切分线，留停顿给观众数；「三份副本」时张开双臂引出副本层 → 收手站到画面下角，避免误挡第三块。 |
| **06 客户端怎么写、怎么读？**「先看写入。」 | 上方先用虚线走 `请求 / 目标`；随后下方用实线走 `客户端 → 甲 → 乙 → 丙`，只跟第二块的一串数据包。反向 ACK 一次，再演示 `查位置 → 直接读甲`，把校验失败后换副本画为单独分支。标签：`问 NameNode；字节直连 DataNode`。 | 在客户端旁面向图解 → 「甲边写边往乙转」时肩臂随传递转向，目光跟到丙；「确认」时回头看客户端；「读呢」时换手指近端副本 → 收臂，让观众看清箭头方向。 |
| **07 机器坏了，怎么办？**「现在让存着第二块的甲失联。」 | 分三拍：`心跳超时 → 读乙`、`2/3 → 乙复制到丁 → 3/3`、`NameNode 服务故障 → Standby 接管（需已部署 HA）`。第三拍保持 DataNode 和块完全不动。标签：`能读 ≠ 副本已补足`、`Secondary NameNode ≠ Standby`。 | 站在机架图外侧 → 「甲失联」时停步、转头并压低原指向手臂；「改走乙」时换手指新的读路；「甲／乙／丁」切换时不跨视线追跑 → 讲到接管时退到图旁侧站，让主备面板接过焦点。 |
| **08 换一个输入检查**「回到镇长的账本。」 | 先重放十二颗的同号卡，`26 → 26`；然后显示 `200 MiB / 128 MiB 块 / 副本因子 3`，先留问题，再揭晓 `2 块 / 6 份副本`。标签：`采集去重；存储留副本`。 | 回到柜台 → 「三十八颗吗」时摊手面向观众，停一拍；「不会」时把重送的卡推回原日志列，保留原文 → 揭晓后点头收势，结束不循环动作。 |

## 角色与讲话动作

- 拟沿用用户提供的 `avatar/mc_mon.png`（64×64 RGBA，细手臂，保留透明外层），同一主持人贯穿。沿用现有基础站姿，再补**双手捧递、交替低头比对、摊手提问、俯身检查、双手叠卡、回头指示、换手指向、退位让图**。这些是连贯的肩、臂、躯干和头部姿势，不要求 MC 手指关节。
- **讲话只缩头，不放大全身。** 皮肤内外层以头部中心一起缩放；样片在句段内约 4 次/秒、不等间隔，`1.00` 到 `1.015–1.021`。思考停顿和读图留白回到 `1.00`，实录后按音节与停顿对齐。点头和转头仍是独立旋转。
- 角色不设固定框，站位、尺度和前后层随镜头变化。为表演可暂挡次要区域，读图时退位或让镜头推到所指目标；不得盖住当前主信息和字幕。持有和放置只用于说明对象和交接：例如手持的 B2 到客户端写入口后，角色让位，焦点交给管线；不同时显示两个道具。其他镜头不用硬加持物。
- 定稿后以实际口播定位关键词；姿势、道具、粒子和推进只读同一全局帧，不使用独立循环计时。减少动态效果时保留状态、方向和关键读图信息。
- 当前[样片](分镜.md)从 **T105 橡木账单 → 角色按台 → 显图 → 放 B2** 切入；再走向右侧操作位，坐着按查询和改读，最后侧卧托头。用动作接触时刻触发图解；镜头之间保留姿态和位置，近景不必露腿。后续铺开八章时沿用这个原则，动作实现集中到 `avatar/`，文稿与原版 Hadoop 不改。
